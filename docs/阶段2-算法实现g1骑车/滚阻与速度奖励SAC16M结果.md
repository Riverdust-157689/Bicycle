# 实验C：滚阻与速度奖励SAC 16M结果

更新日期：2026-11-21。结论：本轮完成训练和128个首回合评测，但仍未形成持续主动踩踏，也没有回合达到20秒。滚阻和速度奖励已启用，不能把本轮结果解释为只差放宽成功指标。

本轮属于实验C：双腿与腰部都进入同一35维策略。此前只控制上半身的14/20维训练属于实验B。已有配置、目录和元数据中的B命名不改名，归属对应见[实验划分与结果索引](实验划分与结果索引.md)。

训练结束时最近1000个完成回合：平均时长9.577秒，原始20秒存活率0.8%，速度合格率0。日志中的即时批次平均速度约1.763 m/s混入了不断重置到2 m/s的新回合，不能作为持续骑行的证据。

## 脚踏和早期动作证据

全部轨迹中，104条回合持续至少5秒。这104条回合在第1秒以后，均未采样到任一脚超过1 N的踏板法向载荷，该阶段采样脚对曲柄正功为0。这里使用GPU保存的20 ms控制边界数据，不保证物理子步间绝无短暂接触；曲柄功率为采样估计。

最长的111号环境撑到18.72秒，曲柄只净转约0.145圈。第1秒双脚载荷已为0；第3秒曲柄速度约0.036 rad/s，第10秒车速约1.522 m/s，之后侧倾失败。视频确认双腿抬起、展开，没有持续踩踏。全身动作也可能经其他接触交换能量，因此只能确认“没有形成脚踏驱动”，不能仅据此证明整段运动完全依赖初始动能。

初始化复核区分了静态接触和动作后的接触：

- 第0帧鞋底—踏板原生碰撞距离约为左-0.127 mm、右-0.109 mm，与GPU已验收初始化一致，没有重置时已有厘米级穿模的证据。
- 111号第一个20 ms控制步后，右脚出现约17 mm穿透，随后脱离。该数值由保存GPU姿态下的原生几何计算得到，没有重新积分CPU动力学。
- 第0号详细记录中，第一步12个腿动作有11个绝对值大于0.95，对应接近关节全行程边界的目标。这说明需要检查动作切换与探索；不等于已经证明执行器或碰撞实现存在错误。

分析产物位于`output/phase2/b_whole_body_rolling_speed_16m_eval/failure_analysis/`：`results.json`为全批次统计，`summary.json`为摘要，`env111_feet.json`等为逐回合脚踏几何与功率分析，`env111_trace.png`为速度、逐脚载荷与曲柄速度曲线。

最长失败回合的2倍慢放视频：`output/phase2/b_whole_body_rolling_speed_16m_env111_render/replay.mp4`。这是GPU保存轨迹回放，不能标为成功样本。

## 学习设置中的待验证问题

当前SAC入口没有覆盖skrl 1.4.2默认的`discount_factor=0.99`。控制周期为0.02秒，折扣时间常数为：

```text
tau = -0.02 / ln(0.99) ≈ 1.99秒
10秒后的奖励权重 = 0.99^500 ≈ 0.00657
```

主动踩踏需要先保持接触、组织双腿配合，再通过曲柄和后轮改善持续速度，其收益可能晚于动作和失稳成本。当前折扣会弱化这部分长期收益。这是有源码依据的风险，但还没有独立对照证明它是失败主因。

腿部探索也存在明显困难：全范围绝对位置目标下，归一化动作0是关节区间中点，并非骑姿；早期随机动作或饱和策略容易先破坏脚踏接触。当前数据支持优先检查探索分布与动作初始化，不支持据此宣布“全量腿控无法学习”。

## 下一步建议与实施边界

以下是待实施、待对照验证的建议，尚未写入算法或新训练配置：

1. 先让折扣时间尺度覆盖骑行任务，例如比较原0.99与候选0.999；后者在20 ms控制下约对应20秒时间常数。需要在入口显式读取并记录配置，不能只向JSON添加未被使用的键。
2. 检查策略初始腿部均值与探索分布，使早期探索从已验收骑姿附近开始。保留全量关节动作与物理可达范围，不据此恢复相位参考或覆盖策略输出；具体映射、初始方差及随机热身方案仍待确定。
3. 用固定车架的主动踩踏小实验隔离接触、腿部探索和曲柄驱动问题。验收必须包含持续正向曲柄转动、脚踏受力与正功；固定车架的结果不能算作自由骑行成功。
4. 通过上述检查后，再做自由人车耦合对照。保持现有滚阻和速度成功指标，继续同时报告原始存活率、速度合格率及脚踏做功，避免多个未验证改动混在同一轮中。

本次文档更新不启动新训练，不修改奖励、折扣因子、动作接口或物理参数。本轮已有测试记录为112项通过、5项CUDA测试跳过；不是对上述待实施建议的验证。

## 评测与失败回放复现

已有输出目录不会覆盖。需要复测时使用新的目录名，例如：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.probe_rider_gpu \
  --controller policy --device cuda:0 --num-envs 128 --steps 1100 \
  --seed 20000 --crank-assistance 0 \
  --source-run runs/b_whole_body_rolling_speed_sac_seed42_16m \
  --first-episodes-only --record-only --record-all-envs \
  --output output/phase2/b_whole_body_rolling_speed_16m_eval_repeat
```

从已有记录重渲染最长失败回合：

```bash
MUJOCO_GL=egl uv run --locked --extra training python -I \
  -m bicycle_sim.cli.render_rider_probe \
  output/phase2/b_whole_body_rolling_speed_16m_eval \
  --env-id 111 --slow-motion 2 \
  --output output/phase2/b_whole_body_rolling_speed_16m_env111_render_repeat
```

本轮没有满足速度要求的成功回合，`--successful`和默认成功回合脚踏审计会报告无可选样本，应使用明确的环境编号检查失败过程。

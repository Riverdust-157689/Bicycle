# 轮地滚阻与无动力滑行检查

本文服务于实验C的全身主动骑行，滑行台架用于物理诊断；不是仅控制上半身的实验B结果。 实验编号及历史文件名对应见[实验划分与结果索引](实验划分与结果索引.md)。

更新至2026-11-21：GPU完整滑行对照及新接触初始化已通过；采用该滚阻和速度奖励的SAC 16M训练也已完成，但尚未形成持续主动踩踏。最新结果见[滚阻与速度奖励SAC16M结果](滚阻与速度奖励SAC16M结果.md)。下文保留物理参数选择与复现过程。

本次检查最初针对策略利用初始动能的问题：抬脚之后维持平衡并滑行，仍可在20秒内获得较高移动奖励。初速为2 m/s；不踩踏而滑行20秒本身并不违背物理，但修改前的模型缺少轮胎滚阻，动力学接近无损滑行，不适合作为需要持续驱动的训练工况。

## 定位与处理

旧轮地接触为`condim=3`，只有切向滑动摩擦；轮胎/地面摩擦0.8，两个轮轴的黏性阻尼均为0.01 N·m·s/rad。增大切向摩擦主要防打滑，不会有效耗散理想纯滚动的能量。

根据[MuJoCo接触模型](https://mujoco.readthedocs.io/en/stable/computation/)，`condim=6`包含滚动摩擦，其系数单位是米，可理解为滚阻力矩臂b，而不是无量纲滑动摩擦系数。近似关系为`M_rr <= b*N`、`Crr ≈ b/R`。当前R=0.27 m，候选b=0.00405 m约对应Crr=0.015。

实现采用两条显式轮胎—地面接触pair，只将这两对接触提升到6维，保留滑动摩擦0.8及既有软接触参数。手、座位、鞋底—踏板、轮胎对其他物体的接触不受该设置影响。扭转项使用后端允许的最小系数1e-5 m；精确零在MuJoCo-Warp的6维摩擦中有NaN警告，不采用。未加入空气阻力、额外轮轴制动力或新的奖励/终止条件。

配置项为`wheel_ground_rolling_friction_m`。缺省/0保持旧模型，非零启用轮地pair。显式pair的摩擦、接触维度和求解参数已纳入初始化物理指纹，不能把旧初始化直接伪装成新模型已验证的初始化。

## 实验与结果

入口：`bicycle_sim.cli.audit_coasting`。自行车使用训练中的椭球碰撞胎，人车总质量43.3942352 kg；以刚性配重代表机器人质量。导轨约束侧移和姿态，允许前进和竖直运动，防止摔车打断滑行测量。导轨不提供前进方向动力，但该实验不是自由人形骑车策略评测。初速2 m/s、两轮初始角速度2/0.27 rad/s，曲柄初始静止；无外力驱动，飞轮应处于超越状态。每组25秒。

原生MuJoCo CPU结果：

| 滑动摩擦 | 滚阻b / m | 10秒速度 / m/s | 20秒速度 / m/s | 首次低于0.1 m/s |
|---|---|---|---|---|
| 0.8 | 0 | 1.880 | 1.767 | 25秒内未达到 |
| 1.6 | 0 | 1.880 | 1.767 | 25秒内未达到 |
| 0.8 | 0.00135 | 1.419 | 0.949 | 25秒内未达到 |
| 0.8 | 0.00270 | 0.961 | 0.229 | 24.3秒 |
| 0.8 | **0.00405** | **0.510** | **0.00486** | **14.8秒** |
| 0.8 | 0.00540 | 0.148 | 0.0000063 | 10.6秒 |

所有无动力正向滑行组的飞轮驱动力矩、功率和做功均为0。证据支持缺少滚阻，而不是飞轮隐藏助推。

候选采用b=0.00405 m。它是偏较大阻力的训练工况，不是实测真实充气轮胎参数；选择目的为减少短时初始动能对训练目标的掩盖。更小的0.00135仍可合理滑行较长时间，不应称为碰撞求解错误。不得为了让某个策略失败而无限加大摩擦。

补充验证：

- 2、1、0.5 ms步长下，候选首次低于0.1 m/s均为14.8秒，10秒速度相差小于0.0001 m/s。
- 相同阻力下施加4 N·m曲柄诊断力矩，20秒速度约2.205 m/s，可以通过传动克服阻力；飞轮本身仍耗散能量。
- 静止2秒没有自发平移；反向滑行也减速；离地且零重力时，平移保持2 m/s，未引入全局黏滞刹车。
- 撤去导轨的配重自行车，在0.001及0.02 rad初始倾斜下仍会超过20度，无控制静态平衡没有被本次设置人为保持。
- 小台架原生MuJoCo与MuJoCo-Warp CPU的0.2秒速度轨迹相差小于1e-5 m/s。后续GPU完整台架也已通过，见下节。
- 新模型CPU座位/双脚/双手初始化检查通过：支持比例和双手接触比例均1.0，最大穿透约0.344 mm。CPU候选不替代GPU初始化验收。

结果：`output/phase2/coasting_audit_v2/results.json`、`validation.json`、`coast_down.png`。初始对照的`coasting_audit`目录保留，最终代码把6维接触扭转项改成后端允许的最小值后，重新跑在v2目录。

## 复现与下一步

CPU完整对照与补充验证：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.audit_coasting \
  --output output/phase2/coasting_audit_cpu_repeat
```

先在训练GPU后端跑同一台架。该命令不加载策略、不训练、不生成新初始化：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.audit_coasting \
  --backend warp --device cuda:0 \
  --output output/phase2/coasting_audit_gpu
```

检查`results.json`：旧模型20秒仍有明显速度；候选20秒应接近停止，低于0.1 m/s时间应接近14.8秒；不出现溢出或非有限值。若有明显CPU/GPU差异，先查明后端，不直接开大预算训练。

独立新配置：`configs/rl/bicycle_b_whole_body_direct_noassist_rolling_sac.json`。全量腿部控制、零曲柄辅助、35维动作、观测与奖励沿用直接控制实验，只新增滚阻、EPA容量128及独立初始化路径。

GPU滑行对照通过后，为新物理模型生成GPU接触初始化：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.settle_whole_body \
  --config configs/rl/bicycle_b_whole_body_direct_noassist_rolling_sac.json \
  --device cuda:0 \
  --output output/phase2/whole_body_rolling_init_gpu
```

成功后写入`assets/references/g1_bicycle_no_weld_rolling.json`，不覆盖原初始化。后续训练必须明确指定新配置和新运行目录。原检查点对应原接触物理，不能把新旧生存率当成同一工况的直接对比。

滚阻修正消除了近乎无损滑行，但没有逻辑上强制每只脚保持踏板或持续做正功。原“20秒存活”判据仍允许停住且不倒；后续应同时查看末段速度、脚踏接触、脚对曲柄功率和净曲柄转向，不能只看存活时长。后续已在独立速度奖励配置中加入持续速度需求；这不是本次物理对照的变量。GPU台架、新初始化和速度奖励SAC 16M均已运行，最新结果见[滚阻与速度奖励SAC16M结果](滚阻与速度奖励SAC16M结果.md)。

## 后续GPU验收与训练状态（2026-11-21）

GPU完整配重台架与CPU一致：b=0.00405 m时10秒速度0.510285 m/s、20秒0.004860 m/s，14.8秒低于0.1 m/s；无滚阻旧模型20秒仍为1.767056 m/s。GPU新接触初始化通过，最大穿透0.537 mm，参考已保存。上面的GPU命令属于已完成实验的复现方法，重跑需使用新输出目录。

加入速度奖励后的全身SAC 16M训练仍未形成持续踩踏，不能据此继续调大摩擦或认定滚阻未生效。配重直线台架与自由全身动作不是同一工况；后者可能经身体和其他接触交换能量，不能直接用台架停车时间推断策略必然何时失稳。

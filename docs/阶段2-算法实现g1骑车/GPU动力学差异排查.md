## 已完成的离线定位

从GPU录制轨迹中取同一个qpos、qvel，载入该次保存的`scene.xml`，恢复下一个控制区间实际执行的双臂目标；其他控制使用原配置，腿部按实际曲柄相位和转速更新参考。原生MuJoCo推进10个2 ms子步，与录制的下一个20 ms状态比较。

对整段1–3秒区间的短步预测，车架前向加速度平均值为CPU约+0.085 m/s²、录制GPU约−0.163 m/s²。为排除机器人内部运动对车架速度的影响，又比较整个机器人与自行车系统的质心速度。以下加速度均投影到采样起点的水平前向：

|采样时间|CPU预测质心加速度|录制GPU质心加速度|
|---|---:|---:|
|0.2秒|+0.011|−0.113|
|1秒|−0.049|−0.194|
|2秒|−0.018|−0.205|
|3秒|+0.026|−0.160|
|4秒|+0.032|−0.184|
|5秒|+0.049|−0.184|

单位为m/s²。这六个采样点的平均差约0.18 m/s²；整车总质量43.394 kg，对应约8 N的水平净力差量级。它是定位线索，尚不是已经确认的错误阻力来源。

整条已录制回合的自由轮瞬时力矩，在相同状态下用原生MuJoCo重算，与GPU记录最大差为0 Nm。这排除了该回合中自由轮瞬时力矩公式不一致这一种解释，但没有排除传动的积分效果或其他执行器差异。

轮地接触是优先检查对象：原生CPU在这些状态下每个轮胎通常只有1个地面接触点；已安装MuJoCo-Warp的`collision_primitive.plane_convex`最多选择4个点，当前网格轮胎在部分采样状态有2–3个顶点位于地面以下。必须读取GPU实际生成的接触点与接触力后才能确定其影响，不能把候选顶点数量当成GPU实际接触点数量。

当前证据表明需要调查后端的有效动力学差异，尚未证明GPU库有软件缺陷。旧轨迹未保存求解器warmstart和每个物理子步完整ctrl；离线重建仍有边界，下面的直接配对检查用于缩小这些不确定性。

## 一次性GPU配对诊断

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.audit_rider_backend \
  output/phase2/b_controls_v4/feedback \
  --gpu --device cuda:0 --output output/phase2/b_backend_gpu_v1
```

命令不训练，在0.2、1、2、3、4、5秒六个已录制状态上，用相同初始姿态、速度、控制目标，分别运行原生MuJoCo与GPU。两者都从零加速度warmstart开始。保存瞬时加速度、被动力/执行器力/约束力、执行器力矩，以及接触几何体、位置、穿透距离和世界坐标接触力；随后按相同控制逻辑推进20 ms，对比整车质心速度。

包含四组消融，每组只在诊断中生效：

|组别|保留/关闭内容|主要用途|
|---|---|---|
|baseline|完整模型|确认直接配对时能否重现差异|
|wheel_contacts_only|只保留轮胎与地面碰撞，保留全部惯性、关节、执行器及座位/手掌约束|区分轮地接触与脚踏/其他碰撞|
|no_contacts|关闭全部碰撞接触，保留其他内容|观察差异是否依赖接触求解|
|no_equalities|关闭座位焊接及两手掌点连接，保留碰撞|观察理想连接与接触耦合的影响|

这些是短时力学定位，不能作为自由骑行成功率。关闭约束或接触后，不要求模型仍能骑行。

输出`report.json`及每组的`*_native.npz`/`*_gpu.npz`。`*_ground_force_ax_mps2`表示采样瞬间地面接触力投影除以总质量，`*_com_ax_mps2`表示20 ms内水平质心速度的平均变化率，两者不应机械要求完全相等。完整原始力、接触位置等用于进一步查看轮胎的接触分布和力矩。

如果完整模型直接配对不能重现原轨迹的减速，先核查warmstart、子步执行历史与数据同步；如果关闭接触后差异消失，继续区分轮地接触与其他碰撞；如果仅关闭理想连接后差异明显减小，再核查约束与接触的耦合。不要先通过增大驱动力掩盖尚未解释的差异。

本次会话没有暴露NVIDIA设备节点，不能执行GPU部分，也不能申请沙箱外执行。原生四组已运行且无求解器警告；CPU测试59项通过，1项CUDA测试跳过。当前新增GPU诊断入口尚需本机运行验证。

## 本机GPU诊断结果：主要差异来自接触

用户已完成`output/phase2/b_backend_gpu_v1`。完整模型的直接短步GPU结果基本复现原录制的质心减速；仅3秒采样存在约0.003 m/s²的小差异，其余点相差约1e-6至1e-5 m/s²。因此此前差异不是只在原生CPU重建中出现。

以下为六个配对状态的GPU相对CPU平均额外质心减速度，正数代表GPU减速更多：

|组别|额外平均减速度 / m/s²|
|---|---:|
|完整模型|0.18132|
|仅轮地接触|0.15713|
|关闭全部接触|0.00000148|
|关闭座位/手掌理想连接|0.07900|

只保留轮地接触仍保留了大部分差异；关闭全部接触后两后端几乎一致。执行器力最大差约5.56e-5，被动力最大差约2.53e-9。现有证据优先指向轮地接触生成及其求解。理想连接会影响差异大小，但不是唯一来源；各消融并非可线性叠加的独立贡献，不能据此做严格百分比归因。

在仅轮地接触的3秒采样中，CPU后轮由轮心前方约1.7 mm的点承受约184 N竖直力，GPU由前方约10.5 mm的点承受约235 N，另外两个候选接触点没有承重。4秒时GPU前后轮承重点也比CPU更靠前。这会改变法向力作用线及滚动阻力，是当前最强线索；候选点多并不意味着它们都在承重。

用户已完成`output/phase2/b_backend_ellipsoid_gpu_v1`。在同样六个录制状态、同样20 ms短步下，比较整车质心水平加速度：

完整模型的平均绝对差下降约94.6%；仅轮地接触的椭球组，两后端均为每个轮胎1个接触点（每个状态总计2个），短步动力学已非常接近。原先系统性额外减速的主要来源已强烈指向网格轮胎的接触表示及其后端处理差异。

完整模型仍有差异：CPU总接触数为16–19，GPU为9–12，瞬时关节加速度、约束力和车架根部加速度仍不完全一致。因此不能说整个机器人系统已经实现CPU/GPU完全一致。剩余差异与其他接触及其约束耦合有关，需要结合后续闭环表现判断影响。

这里使用平均绝对差评估误差，避免完整模型的正负差相互抵消，让均值−0.00109看起来比真实逐点误差更小。

下一步应把椭球作为候选碰撞模型进行完整GPU零动作/反馈＋IK长回合验证，检查速度保持与20秒生存率，然后再决定是否作为训练模型并重新训练SAC。此时生产资产、训练配置尚未切换；侧向轮廓曲率改变的影响也尚未验证。

## 椭球SAC短训与轮胎适用边界

`runs/b_sac_ellipsoid_pilot_seed42`正常完成1,048,576次交互，策略已更新，源文件与相位参考哈希均匹配。14,182个完成回合全部因倾角超限终止，20秒生存率0%；平均时长1.4722秒，最后1000回合平均1.3606秒，训练期间最好的近期均值1.5525秒。上一轮网格SAC累计平均1.4618秒，因此这次仅提高约0.71%，没有持续学习改善。尚未独立评测新权重的均值策略。

轮胎接触差异影响了反馈控制器长回合表现，但消除这种差异没有自动解决SAC学习失败，不能继续将SAC失败主要归因于该项GPU减速现象。

![SAC复验与胎冠截面对比](../../output/phase2/b_sac_ellipsoid_analysis/training_and_profile.png)

当前椭球可以作为理想化刚性轮的算法基线，尚不是已标定的真实自行车轮胎。经典[Meijaard等人的自行车平衡基准](https://bicycle.tudelft.nl/schwab/Publications/meijaard2007linearized.pdf)采用理想刀刃轮和无滑滚动点接触，说明研究平衡并不必然需要复杂充气轮胎。但这不等于本项目的MuJoCo软接触椭球已符合该基准或真实车辆。

当前半径R=0.27 m、半宽b=0.018 m。在胎顶横向截面，椭球的曲率半径为b²/R=0.0012 m，即1.2 mm；原圆冠连续设计的截面半径为18 mm。两者轮径和最大宽度相同，并没有保持相同的胎冠几何。该变化会影响侧倾时的接触点位置及力矩，20秒无扰动、±0.02 rad初始侧倾的通过结果不足以校准这些性质。

软接触参数是通用接触阻抗/耗散参数，不能直接当成胎压或橡胶材料参数。目前轮地使用condim=3、friction=[0.8,0,0]，包含法向与滑动摩擦，未显式建模滚动摩擦、胎压变形或轮胎侧偏力曲线。[MuJoCo接触模型说明](https://mujoco.readthedocs.io/en/stable/computation/#contact)区分了这些接触自由度，condim=6才增加滚动摩擦自由度；不应把这个选项本身等同完整轮胎模型。

因此先将椭球限定为算法调试基线，不据此宣称真实骑行或技能迁移已验证。后续轮胎验证应覆盖直行滑行减速、不同速度下的侧倾/转向响应及对胎冠参数的敏感性，并与可信基准或实验数据比较。

当前先独立评测均值策略，避免只根据带探索噪声的训练曲线判断最终策略：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.train_rider \
  --algorithm sac --device cuda:0 \
  --evaluate runs/b_sac_ellipsoid_pilot_seed42/final.pt \
  --seed 20000 --num-envs 128 --transitions 262144 \
  --output output/phase2/b_sac_ellipsoid_eval_seed20000
```

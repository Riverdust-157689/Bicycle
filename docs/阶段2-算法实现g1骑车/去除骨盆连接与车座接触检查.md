# 去除骨盆连接前的车座接触检查

本文是从实验B转向实验C全身控制前的接触支撑检查，固定车架台架通过不代表C自由骑行成功。 实验编号及历史文件名对应见[实验划分与结果索引](实验划分与结果索引.md)。

日期：2026-11-20。

建议先采用现有平座，座面从0.770 m升至约0.7871 m，保持水平、滑动摩擦系数0.6和现有软接触参数。固定车架的原生CPU与GPU台架均已验证该修改能建立真实骨盆支撑；没有证据要求立即增加包裹结构或显著增大摩擦。自由骑行仍需单独验收。

## 原始问题

当前自然抓握参考姿态中，骨盆碰撞网格最低点为约0.78763 m，原车座顶面0.770 m，相差17.63 mm。初始状态没有骨盆—车座接触，而旧任务的骨盆weld能够传递支撑力和力矩。直接删除weld不等于已经得到合理的坐姿初始化。

G1骨盆底部比上部窄，当前使用网格的凸碰撞外壳。检查依据是编译后的碰撞几何，不是视觉网格外观。将座面升高17.13 mm，保留约0.5 mm初始间隙，可以在基本不改变原手脚几何的情况下，通过重力沉降建立支撑；随后仍应生成无weld的新初始化参考，不能把旧固定骨盆参考直接当成最终重置状态。

## 台架条件与测量

新增`bicycle_sim.cli.audit_saddle_contact`：固定自行车车架，机器人基座自由，删除全部座位/掌把equality，保留真实手把、脚踏接触。双臂/腰部采用原名义PD，手指名义闭合0.9；双腿采用原相位参考与速度前馈。静态条件曲柄速度命令为0，动态条件曲柄速度命令为3.7037 rad/s、力矩上限8 Nm。这不是35维策略，也不是自由骑行验证。

每例6秒，从1秒后统计骨盆支撑比例与平均座面竖直支撑力。动态条件下，推荐平座的曲柄实际转约2.39圈，1秒后平均角速度约2.51 rad/s，并未精确达到命令转速。

共完成16例名义对照：原座面、升高平座、升高椭球座面、两条纵向圆垫、升高平座摩擦0.3/0.9、升高平座绕横轴±3度，分别静态和转踏板。全部未使用骨盆或手部连接约束。

## 结果

以下为转踏板条件；位移是6秒末相对初始骨盆位置的水平位移，支撑比例指采样时骨盆—座面竖直支撑力大于1 N。

| 方案 | 平均座面竖直支撑力 | 骨盆支撑比例 | 最终水平位移 | 最大座面接触穿透 |
| --- | ---: | ---: | ---: | ---: |
| 原高度平座 | 0.12 N | 0% | 10.3 mm | 0.011 mm |
| 升高17.13 mm平座 | 152.0 N | 100% | 1.79 mm | 0.591 mm |
| 相同顶高椭球座面 | 152.3 N | 100% | 1.95 mm | 0.589 mm |
| 双纵向圆垫 | 155.0 N | 100% | 1.50 mm | 0.586 mm |

原座面约0.12 N的微小载荷来自髋部连杆的偶发接触，不是骨盆落座。原座面静态条件完全不承重，机器人仍可能靠手脚支撑而不明显下落，所以“不掉下来”不能证明座面有效。

机器人质量约34.39 kg、重力约337.4 N。推荐平座静态承重约138.2 N，转踏板约152.0 N，其余支撑由系统其他接触承担；不能要求车座独自承担全部体重。推荐平座两种条件下均无座面—其他机器人连杆接触记录、无求解器警告。它的单点或有限接触并不等于weld，不能直接锁定骨盆姿态。

改变摩擦至0.3或0.9、座面倾角±3度均能在本台架建立支撑，没有显示需要通过高摩擦或倾斜才能落座。椭球和双圆垫略有差别，但当前短台架不足以证明其在全身策略中更优。

另完成6例外力检查：转踏板条件下，在3.0–3.2秒向骨盆施加40 N前向或横向力，平座摩擦分别0.3/0.6/0.9。摩擦0.6时最大水平位移约2.05/2.62 mm；0.3横向例约4.01 mm，支撑比例约99.2%。这些结果包含手脚PD和接触的共同作用，不能解释为车座单独能够抵御这些外力，也不是摩擦系数的实物标定。

## 参数与结构建议

1. 优先只升高座面17.13 mm；正式修改时延长座管顶部，使其与新座底相接，不整体移动机器人、车架或车把。当前台架变体仅改变接触座面，原资产没有修改。
2. 保留0.20×0.13 m平座尺寸和水平姿态，暂不增加侧挡、背靠、绑带或其他等效固定结构。双圆垫保留为候选，若更大运动范围下出现明显侧滑再比较。
3. 摩擦维持`[0.6, 0, 0]`、`condim=3`。不添加扭转/滚动摩擦来人为锁定骨盆。
4. 暂保留`solref=[0.02,1]`、`solimp=[0.9,0.95,0.001,0.5,2]`。约0.6 mm数值穿透在本台架中未伴随警告，但不是对真实坐垫材料的标定。
5. 新初始化应在无weld条件下沉降，检查骨盆、手把和脚踏同时接触及关节状态，再保存项目参考资产。全身动作放开后需重新检查腿部运动范围内的座面干涉。

## 复现与GPU下一步

原生CPU全套与外力检查（使用新的输出目录）：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.audit_saddle_contact \
  --output output/phase2/saddle_contact_cpu_recheck

uv run --locked --extra training python -I -m bicycle_sim.cli.audit_saddle_contact \
  --suite push --output output/phase2/saddle_contact_push_recheck

uv run --locked --extra training python tools/plot_saddle_contact.py \
  output/phase2/saddle_contact_cpu_recheck
```

GPU先只对比原座面与推荐平座，四例各6秒；直接提取Warp求解器的接触力，使用canonical geom编号，不在CPU重新求解接触：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.audit_saddle_contact \
  --device cuda:0 --only original raised_box \
  --output output/phase2/saddle_contact_gpu_v1
```

本会话CUDA不可见，用户已在外部GPU完成上述四例测试，结果见下节。相关单元测试5项通过、1项CUDA跳过，包含接触建立、骨盆抬起后自然脱离、无equality、质量/惯量保持不变和重复编译的关节映射。台架成功不代表旧20维策略删除weld后仍能骑行。

## GPU台架结果

`output/phase2/saddle_contact_gpu_v1/results.json`四例均正常完成约6秒，记录源码及输入文件哈希与检查时工作区一致，使用Warp直接接触力。没有发生入口检查的容量溢出或非有限状态中断；GPU报告中的`warnings=null`不等于已读取CPU求解器警告。

| 条件 | 平均座面竖直支撑 | 骨盆支撑比例 | 最大水平位移 | 最大座面穿透 |
| --- | ---: | ---: | ---: | ---: |
| 原座面，零曲柄速度命令 | 2.09 N | 7.2% | 9.24 mm | 0.367 mm |
| 原座面，转踏板 | 0.65 N | 2.0% | 11.60 mm | 0.276 mm |
| 升高平座，零曲柄速度命令 | 219.1 N | 100% | 1.15 mm | 0.646 mm |
| 升高平座，转踏板 | 195.9 N | 100% | 2.12 mm | 0.617 mm |

升高平座动态条件下，骨盆最终水平位移约1.24 mm、下降0.59 mm；最大绝对倾角约1.02度，座面只与骨盆碰撞，没有其他机器人连杆接触记录。1秒后骨盆支撑力采样范围约77.3–260.8 N。该组结果支持“升高现有平座、摩擦0.6、水平姿态”作为无weld任务的起始方案。

CPU/GPU仍有明显定量差异：推荐平座静态支撑138.2→219.1 N（+58.5%），动态152.0→195.9 N（+28.9%）；动态曲柄1秒后平均角速度2.51→1.97 rad/s，GPU约转1.74圈。零速度命令也不是曲柄角度锁定，GPU原座面条件实际发生倒转。因此这些条件应按速度命令理解，不能描述为全部严格静止或严格定速。

当前测试不能唯一判断载荷差异来自座面接触还是手脚接触及控制跟踪的共同作用，未对这些因素做分离对照。两端均能持续建立推荐座面的骨盆支撑，尚无必要仅为使平均力一致而调整摩擦。训练以GPU为实际后端，下一步应在GPU生成无weld的沉降初始姿态，同时检查手指、脚踏及车座载荷，再接入35维策略。

GPU对比图：`output/phase2/saddle_contact_gpu_v1/seat_comparison.png`。剖面图仅从保存姿态重建几何；载荷曲线使用GPU直接记录，未用CPU动力学重新生成。

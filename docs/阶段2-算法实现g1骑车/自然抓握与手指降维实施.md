# 自然抓握与手指降维：首版实现与推进顺序

本文记录实验B中抓握控制的引入，该6维手指接口后续由实验C沿用；全身控制的实验归属另列。 实验编号及历史文件名对应见[实验划分与结果索引](实验划分与结果索引.md)。

目标：取消掌把理想点连接，以实际手指/手掌与车把的碰撞、法向力和摩擦传递转向作用。保留旧实验用于比较，先验收抓握，再接入自由骑行和RL。

## 控制接口

本地Dex3模型与[宇树官方说明](https://www.unitree.com/cn/Dex3-1)一致：每手三指、7个运动关节，拇指3关节、食指与中指各2关节。采用每指一个归一化闭合量，双手共6维，顺序为：

`left_thumb, left_index, left_middle, right_thumb, right_index, right_middle`

首版`control/hand_synergy.py`保留14个实际手指电机，用一个输入为同一手指的多个关节产生协同目标：

`q_target = q_open + u * (q_closed - q_open), u in [0,1]`

拇指外展/对掌关节暂保持预设姿态，另外两个关节随闭合量变化；食指、中指各自的两个关节联动。左右手的闭合符号按本地关节轴镜像处理。关节限位和原模型力矩上限保留。

这属于软件协同降维，**不是机械欠驱动**。Dex3实际是全驱动手；将其改成每指一根腱、一个执行器、其余关节被动跟随，会改变实际机构。若后续要比较真正的欠驱动，应单独建立有弹性/限矩的腱驱动版本，并与实际硬件可实现的控制策略区分。不能仅用刚性关节比例约束就宣称具备接触自适应。

当前指关节使用有限力矩位置PD，测试值kp=5 N·m/rad、kv=0.15 N·m·s/rad，闭合输入最大变化率0.5/s。这些是未硬件标定的仿真起点。接触阻挡时关节可达不到目标，未新增手指或掌把刚性连接。

## 已实现的隔离台架

`cli/probe_hand_grasp.py`固定车架，保留座位连接和身体名义姿态，删除两条掌把connect约束，仅通过真实接触握把；没有转向电机。该台架不代表自由骑行或RL成功。

第一次闭合只有拇指接触，食指、中指未包住。进一步检查几何后：

- 将每手预抓握位置沿手指反方向后退5 mm，IK保持掌面朝向。
- 调整食指、中指闭合轨迹，使近端能绕到把手外侧。
- 默认闭合输入为0.9；手指PD较原来保持张开时的高刚度设置降低。

调整后，初始手掌与车把有约0.57 mm间隙，没有初始穿透；旧“掌面微接触”验收上限0.2 mm不适用于这个预抓握间隙。正常闭合后六指均形成承重接触。

## CPU接触传力结果

12秒测试先缓慢闭合，4–6秒由双臂带动转向至+0.1 rad，8–10秒带动至−0.1 rad。运行中只下发关节目标和电机驱动，不直接设置转向qpos。

|稳态窗口|参考转向|实际平均转向|转角RMS|六指均受力接触比例|
|---|---:|---:|---:|---:|
|3–4秒|0|−0.00019 rad|0.00019 rad|100%|
|6.5–7.9秒|+0.1 rad|+0.10060 rad|0.00061 rad|100%|
|10.5–11.9秒|−0.1 rad|−0.10105 rad|0.00106 rad|100%|

无求解器警告，状态有限。上述窗口最深指把软接触穿透约0.48 mm。不同手指的汇总法向力约17–45 N，这还不是实际Dex3抓力的标定结果。

## 下一步GPU对照

已为同一台架增加MuJoCo-Warp入口，读取GPU求解器实际接触和力，不用CPU重新生成接触。当前会话没有CUDA，该入口仍需本机运行验证。

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.probe_hand_grasp \
  --device cuda:0 --seconds 12 --steer-test \
  --output output/phase2/hand_contact_steer_gpu_v1
```

CPU可复现命令：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.probe_hand_grasp \
  --seconds 12 --steer-test --output output/phase2/hand_contact_steer_cpu_new
```

输出包含场景、初始状态、姿态轨迹、逐指接触力、转角及各稳态窗口统计。`contact_transfer_check_passed`只表示这个台架上的接触传力检查通过，不代表真实硬件抓握可靠或骑行成功。

## 接入RL的顺序

1. 先让GPU台架保持接触并传递±0.1 rad转向，再逐渐扩大转向范围和测试抗滑移能力。
2. 保持六指闭合输入为已验收值，移到自由自行车上，复验反馈＋双臂控制能否维持行进平衡；座位、曲柄驱动和腿部参考按当前阶段保留，掌把连接取消。
3. 再加入手指策略输入：双臂14维＋手指6维，共20维。初始以稳定握持为名义状态，先允许小幅手指调节，再扩大松/握范围；补充真实接触和滑移诊断。

原14维策略、默认训练场景和旧检查点没有切换为新任务。增加接触与动作自由度不会自动解决学习失败，需将抓握失败、滑移与平衡失败分别观察。

## 首轮GPU台架：转向跟踪有效，接触统计存在采集缺陷

用户完成`output/phase2/hand_contact_steer_gpu_v1`。与CPU台架的初始qpos、ctrl最大差均为0，模型仅有座位连接，无掌把连接、无转向电机，状态有限。

|参考转向|GPU稳态平均实际转向|GPU稳态RMS|
|---|---:|---:|
|0|−0.000223 rad|0.000223 rad|
|+0.1 rad|+0.100755 rad|0.000758 rad|
|−0.1 rad|−0.101626 rad|0.001632 rad|

转向指标很好，但旧程序报告全部手指接触为零，不能据此判断六指抓握失败：已经定位并复现了采集兼容性缺陷。当前MuJoCo头文件将`mjContact.geom1/geom2`标记为deprecated，建议使用`geom[0]/geom[1]`。MuJoCo-Warp的`get_data_into`只填充后者；先前采集读取旧字段，会把本来存在的车把接触全部过滤掉。

已修复为读取canonical `contact.geom`，GPU接触力直接通过`mujoco_warp.contact_force`取得，避免依赖CPU约束索引重排。新增回归测试模拟“canonical几何体编号有效、旧字段仍为0”，验证指端接触和受力仍能正确识别。并增加总接触数、车把接触数及原始接触几何、位置、局部力等记录，便于之后复查。

原始results.json未修改，旁边`assessment.json`明确标记旧接触力/接触率/穿透统计及旧总验收标志不可用；旧转角与姿态数据仍有效。已经从该次真实GPU姿态生成[GPU回放视频](../../output/phase2/hand_contact_steer_gpu_v1/render/grasp.mp4)，画面标明来源及接触力统计待验证。

由于旧运行没有保存有效的指端接触力，不能用原生CPU重新计算的接触力替代原GPU值。需在修复后用新目录重跑12秒：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.probe_hand_grasp \
  --device cuda:0 --seconds 12 --steer-test \
  --output output/phase2/hand_contact_steer_gpu_v2
```

当前尚不能宣称GPU六指握持验收已通过，也不直接进入自然抓握骑行训练。转向跟踪已有正面证据，下一次主要补齐正确的GPU接触数据。

## 修复后GPU台架通过及闭合程度的准确含义

`output/phase2/hand_contact_steer_gpu_v2`的canonical接触编号与直接Warp接触力采集已生效，`contact_transfer_check_passed=true`。三个验收窗口六指均受力接触比例都是100%；零/正/负转角稳态RMS分别约0.000223/0.000753/0.001539 rad，窗口最深软接触穿透约0.49 mm。

### 闭合输入与关节目标

当前六个输入均由程序固定为0.9，没有RL参与选择，也没有接触力达到某个阈值就停止闭合的逻辑。u=0.9表示从预设张开姿态走向预设闭合姿态的90%目标插值，不表示90%关节行程、90%最大力或实际已经闭合90%。

闭合状态从0以0.5/s变化，约1.8秒到0.9。关节目标为`q_open + u*(q_closed-q_open)`并受原关节范围限制。当前张开角接近0，左手目标为：

|手指|u=1的预设闭合角|u=0.9的目标角|
|---|---|---|
|拇指弯曲两关节|1.0、1.2 rad|0.90、1.08 rad|
|食指两关节|−1.5、−1.6 rad|−1.35、−1.44 rad|
|中指两关节|−1.5、−1.6 rad|−1.35、−1.44 rad|

右手弯曲符号镜像。拇指第0关节的目标保持初始对掌角（当前约0），仍由PD控制而非机械锁止。

各关节独立PD：`tau = clip(5*(q_target-q) - 0.15*qdot, original torque limits)`。弯曲关节原力矩上限为±1.4 N·m，拇指第0关节±2.45 N·m；这些是所用模型的参数，不是本次硬件标定结果。碰到车把后，真实角度可能达不到目标，位置误差转为有限夹持力矩，并由接触求解器产生反力。

例如GPU约3秒时，左拇指弯曲实际角约0.621、1.053 rad，食指实际约−1.212、−1.415 rad，说明其实际状态与目标角并不相同。3–4秒静止握持窗口中，单手拇指汇总法向力均值约44.5 N，食指/中指各约22 N。这里是各手指与车把接触点的法向力之和，不是已经标定的整体抓力或单一方向合力。

### 上肢转向控制

台架的双臂同样没有RL：先用IK计算0、+0.1、−0.1 rad车把角对应的手臂姿态，再按时间平滑插值关节目标，交给原手臂有限力矩PD执行。预抓握后4–6秒转向正侧，8–10秒转向负侧。实际车把角由指掌接触传力形成，运行中没有直接改车把角或使用转向电机。

所以目前是“每指一维的软件协同＋独立关节PD”，不是一根腱分配拉力的机械欠驱动，也还没有按接触力/滑移自适应调整闭合量。该台架验证了u=0.9在本模型与该小幅转向条件下可以保持接触并传力，并未证明这是最小必要握力、硬件安全握力，或已覆盖自由骑行。

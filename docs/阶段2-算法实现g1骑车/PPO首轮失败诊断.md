> 当前更新：GPU逐帧轨迹已确认控制器确实执行，约5.54秒触及旧转向参考上限后进一步失稳。已扩大控制范围，允许直接开展SAC短预算试验，无需等待CPU/GPU完全一致。实测证据、当前参数及命令见[侧倾反馈与双臂IK回放](侧倾反馈与双臂IK回放.md)。下文保留首轮PPO的历史诊断。

结论：先修正PPO动作采样并确认GPU上的手臂转向链可控，再跑短预算复验。SAC值得作为后续对照，但当前不建议直接再花完整839万交互。尚未重训，不能宣布修正已解决收敛问题。

## 实际训练结果

该次在RTX 4060 Laptop GPU上运行65536个向量步、128环境，共8,388,608次控制步交互，约2341秒。105086个完成回合中没有一个持续20秒，平均回合1.595秒，平均回报−2.926。前后不同训练区间的回合长度基本停留在1.58–1.61秒，几乎没有增长。

训练确实执行了更新：检查点有优化器状态，策略参数改变，value loss从早期约0.67/2.06降到约0.08，动作标准差没有整体塌缩为零。value loss下降只表明拟合当前失败回合，不是学会平衡。

检查时，保存的源文件哈希与工作区一致，相位参考哈希一致。当前GPU不可见，因此以下额外物理对照使用保存的`scene.xml`在原生CPU MuJoCo上进行，不冒充GPU评估。

## 已确认的问题：PPO动作与概率不匹配

旧PPO模型的实现为：网络输出经tanh作为高斯均值，GaussianMixin采样后先把动作截断到[-1,1]，再对截断值计算普通高斯log-prob。安装版本的源码确认了这个顺序。被截断的随机变量在边界有概率质量，普通高斯密度不能准确描述这个分布。

在独立CPU回放访问的策略状态上，最终策略约51.9%的均值绝对值>0.95。根据各关节保存的标准差计算，单关节采样越界概率平均约31.4%，每步至少一维越界概率约99.3%。**这是模型分布在CPU回放状态上的概率计算，不是直接记录到的GPU训练裁剪次数**。这一问题及均值tanh饱和会干扰优化，但是否是失败的主要原因仍需要修正后的对照训练确认。

现增加`ppo_raw_gaussian=true`：

- PPO使用无tanh均值的高斯策略，保留原始采样和对应log-prob进入rollout。
- 环境执行时才限幅，原有±0.25 rad关节偏移及2 rad/s目标变化率仍然生效。
- 原始动作、log-prob、执行后状态之间关系一致；不修改skrl源码。
- 旧run缺少新标记时仍按旧模式加载，旧权重不会被偷偷解释为新策略。
- SAC仍采用原有重参数化tanh Gaussian及其Jacobian，没有同时修改它的算法。

接口依据：[skrl Gaussian模型](https://skrl.readthedocs.io/en/1.4.2/api/models/gaussian.html)；具体采样／截断／log-prob顺序以本项目安装的1.4.2源码为核查对象。这里只调整项目模型配置，非重新实现PPO。

## 可控性与探索难度

在固定车架上，双臂联合IK目标能够在±0.25 rad各关节偏移范围内，将车把带到约±0.15 rad；更大目标±0.25 rad时实际约±0.236 rad。因此不是手臂完全无法转向，但可用范围存在限制。

随后用同一辅助人车模型、相同曲柄伺服和腿部参考，去掉车架固定，仅替换双臂目标生成方式。使用：

```text
目标转向 ≈ −3*车辆侧倾角 −0.7*车体系侧倾角速度
目标转向 → 双臂IK关节目标 → 原有PD及掌把连接 → 真实转向
```

没有直接转向执行器，没有世界平衡力。该手工控制器的增益经过小范围CPU试调，**仅用于诊断可控性，不作为新RL算法或正式方法比较**。

另取未用于上述试调的初始种子20000–20009，结果：

| 控制方式 | 平均持续时间 | 20秒生存率 |
| --- | --- | --- |
| 双臂保持名义姿态 | 1.592 s | 0/10 |
| 零均值随机双臂动作 | 1.648 s | 0/10 |
| 已训练PPO的确定性均值动作 | 1.530 s | 0/10 |
| 侧倾反馈＋联合双臂IK | 20.000 s | 10/10 |

CPU失败回合均因倾角越限，未发现非轮胎触地先于倾倒。不能据此排除GPU中特有的问题，尤其旧GPU日志缺少逐项终止原因。

这说明当前模型在这些小初始扰动条件下可控；14个关节独立探索必须额外学会双手协调，随机动作可能相互拉扯、产生无效内力。该解释有物理依据，但尚无不同动作维度的学习消融，不能直接断言14维本身就是主因。

## 已补充的诊断能力

- 最近1000个完成回合的生存率／平均时长，避免只看历史累计量。
- 倾角失败和非轮胎触地失败分别记录；两项可能同时发生，不能简单相加当作互斥分类。
- 新策略输出越界比例、执行动作幅度、转向幅度与平均倾角。
- 原始高斯动作和对应log-prob的回归测试。
- `diagnose_rider`用保存场景、原始相位参考哈希、旧策略模式做CPU对照；可保存所有回放序列。
- `probe_rider_gpu`在实际GPU上运行同一手工联合控制器，检验仿真与传力链，不学习、不产生策略检查点。

当前50项CPU测试通过、1项CUDA回归测试跳过。本次没有实际重训，GPU探针也需要在用户GPU上运行。

## 推荐执行顺序

先跑GPU控制器探针，约1100个控制步，前1000步对应20秒：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.probe_rider_gpu \
  --device cuda:0 --num-envs 32 --steps 1100 --seed 20000 \
  --output output/phase2/b_gpu_controller_probe
```

探针完成回合生存率低于90%时返回失败，结果仍保存在results.json。应查看生存率和失败原因，不预设GPU必然复制CPU的10/10。如果该探针也很快失败，应先处理CPU/GPU动力学、接触或执行链的一致性；此时换SAC没有解决根因。

探针能稳定后，用修正后的PPO从头做约100万交互复验，不接着旧优化器继续：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.train_rider \
  --algorithm ppo --device cuda:0 --num-envs 128 --seed 42 \
  --transitions 1048576 --output runs/b_ppo_v3_pilot_seed42
```

先看`recent_mean_episode_seconds`是否持续超过原来约1.6秒，转向是否随侧倾恢复；不要求100万步已经通过20秒验收。若仍基本无进步，下一步优先验证将动作改为协调转向意图、通过固定IK映射至双臂，区分“平衡学不会”和“手臂协调学不会”。这将是独立、明确标记的实验，当前还没有替换14维任务。

SAC可在修正并验证后的同一任务上先跑短预算对照，再决定是否扩展。SAC的策略本来已经使用正确的tanh变换，但它仍面对相同的接触、动作协调和控制权限；换算法没有必然解决这些问题的保证。尚无SAC训练结果，不作优劣判断。

复现CPU诊断与图片：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.diagnose_rider \
  runs/b_ppo_v2_seed42 --episodes 10 --seed 20000
uv run --locked --extra training python -I tools/plot_rider_diagnosis.py
```

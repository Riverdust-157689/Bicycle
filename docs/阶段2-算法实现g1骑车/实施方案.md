> 最新状态（2026-11-21）：当前主线为实验C：无骨盆/掌把连接、零曲柄辅助的35维全身骑行控制。轮地滚阻与固定2 m/s速度奖励已接入，GPU SAC 16M训练及128个首回合评测完成，但20秒存活率和速度合格率均为0，尚未形成持续主动踩踏。设置、证据与下一步建议见[滚阻与速度奖励SAC16M结果](滚阻与速度奖励SAC16M结果.md)，实现与命令见[35维全身控制](无骨盆连接的35维全身控制.md)。下文A/B教师分层方案及[B-GPU训练说明](B-GPU训练说明.md)保留为早期规划和实验记录，不代表最新控制与辅助设置。

本轮建立可训练、可评估的 model-free 基线；可微分世界模型留待基线可靠后引入，不增加预测网络、规划器或技能迁移损失。

## 1. 先修正传动

保留当前确认的车架、轮胎、转向几何和 2:1 传动比，替换双向角度等式约束。设曲柄、后轮的正向角速度分别为 `ωc、ωr`，传动比 `G=2`：

```text
slip = G*ωc - ωr
T = clip(k*slip, 0, Tmax)
后轮传动扭矩 = +T
曲柄反扭矩   = -G*T
```

实现采用 MuJoCo 原生 fixed tendon＋general actuator：腱速度是 `slip`，固定增益为零，仿射速度偏置为 `-k*slip`，力限制为 `[-Tmax, 0]`。它虽然占用一个 actuator 编号，但不接受动力指令；不存在独立后轮电机，无 Python 回调，也无需每步切换约束。CPU 已验证；原生表达式是否在当前 MuJoCo Warp 后端取得一致结果，须另行验收。

- 正踩追上后轮转速时，传动接合，同时给曲柄反作用力。
- 倒踩、后轮前进滑行且曲柄不动、后轮超越曲柄时，传动扭矩为零。
- `P = T*ωr - G*T*ωc = -T*slip ≤ 0`：传动本身不产生机械能。
- 这里的“轮转不反拖”针对**前进滑行**。后轮倒转时真实棘轮可能接合并反拖曲柄；不额外实现一个与真实自由轮矛盾的双向脱开规则。

当前 `k=0.5 N·m·s/rad`，后轮扭矩限幅 `6 N·m`。这是有滑差、有耗散的单向传动近似，不是刚性棘轮或可辨识的真实链条模型；不能再要求累积角度满足 `qr=2*qc`。较大 k 在分支关节和离散积分下可能恶化稳定性，不以盲目增大 k 消除滑差。

验收包括：倒踩与滑行无传动力矩、正踩有后轮驱动力、反作用力比例正确、瞬时传动功率不为正、2/1/0.5 ms 步长比较、无求解器警告。隔离台架中，1 N·m 正踩 1 秒，2 ms 与 1 ms 的后轮转角相差约 2.3%；2 ms 与 0.5 ms 相差约 3.5%。这只是首版数值容差，受载骑行还要复查。轮轴自身阻尼仍会让滑行减速，与后轮反拖曲柄是两件事。

## 2. 实验 A：纯自行车目标条件 RL

### 任务和控制边界

水平地面上的自由自行车，在行进中维持平衡，跟踪目标速度大小 `v*` 和世界坐标下的绝对目标航向 `ψ*`。第一版目标是方向，不是某个空间位置，因此不引入 waypoint、路径投影或到达奖励。

策略输出两个归一化动作：

| 动作 | 映射与执行 |
| --- | --- |
| 曲柄目标角速度 | `[−1,1] → [0,10] rad/s`；有限力矩速度伺服，`kv=2`、最大曲柄力矩 `8 N·m` |
| 转向立管目标角 | `[−1,1] → [−0.35,0.35] rad`；角度目标限速 `1.5 rad/s`，位置伺服 `kp=25、kv=2`、最大转向力矩 `8 N·m` |

动作不是直接覆盖 qpos/qvel，不施加世界坐标平衡力，不固定车架。曲柄伺服可以制动曲柄，但自由轮脱开后不能通过曲柄制动前进中的后轮。

第一版没有刹车，所以不要求任意快的降速、倒车、原地平衡或零速起步。先在 `1.5–3.0 m/s` 内做温和速度切换，降速靠滑行损耗；若后续确需快速降速，再明确增加刹车执行器与动作，不能偷偷恢复双向传动。

物理步长 `2 ms`，每 10 个物理步更新动作一次，即 `50 Hz`。先给定 `2 m/s` 初始前进速度，车轮初速与地速一致。初始侧倾仅在 `±0.02 rad` 采样，避免完全对称状态掩盖平衡问题；这是初始条件覆盖，运行过程中不加推力、外力脉冲或参数随机化。

### 目标与状态

每 5 秒采样速度目标，以及相对当前实际航向 `±0.35 rad` 的新方向，随后将方向转为**固定的世界坐标目标**，直到下一次更新。目标不是每个控制步跟着车头移动的相对方向。初始世界航向随机，避免策略只会沿 +X 骑。

首版观测 25 维：

- 车架世界线速度 3、世界角速度 3。
- 世界航向的 cos/sin 2、车体系重力方向 3。
- 转向角和角速度 2、曲柄相位 cos/sin 2、曲柄与前后轮转速 3。
- 目标速度 1、世界目标方向 cos/sin 2。
- 上一步实际限幅动作 2、限速后的转向伺服目标 1、距下一次目标切换的归一化时间 1。

角度用 sin/cos 避免 ±π 跳变。伺服目标属于有记忆的执行器状态，不能只观察关节角却隐藏限速器状态。无需输入世界绝对位置；方向跟踪对平移不敏感。观测使用 RSL-RL 自带运行归一化。

### 奖励与终止

目标世界速度向量为 `v*xy = v*[cos ψ*, sin ψ*]`。首版奖励率为：

```text
  2.0 * exp(-||vxy - v*xy||² / 0.6²)
- 0.5 * ||vxy - v*xy||²                  # 速度偏差大时仍有区分度
+ 0.5 * exp(-wrap(ψ-ψ*)² / 0.5²)
+ 0.2                                   # 存活
- 0.2 * max(0, |roll|-0.26)²             # 只轻惩罚较大侧倾
- 0.01 * ||ωworld||²
- 0.01 * ||a-aprev||²
```

第一轮训练发现指数奖励在误差大时饱和，策略通过高速行驶获得稳定性却不跟踪目标，因此加入可配置的连续速度误差惩罚；没有引入新的算法模块。每步乘控制周期，失败额外扣 1。航向与速度分别约束车头和实际运动方向，避免横滑满足其中一项。不给强制零侧倾的高权重目标，以免妨碍转弯；不一开始引入协调转弯解析参考或对称性损失。

失败：侧倾超过 `0.65 rad`、俯仰超过 `0.6 rad`，或非轮胎部件触地。20 秒为时间截断，不计为倾倒；向 PPO 提供 timeout 标记。MuJoCo 警告、非有限状态直接停止并排查，不能用自动复位掩盖数值异常。

### 算法与推进顺序

首版复用项目锁定环境中已有的 **RSL-RL PPO**，MLP `[128,128]`，不自写 PPO。mjlab 官方也以 RSL-RL 提供 on-policy 训练接口；选择它是为了复用现有依赖，不是根据调研断言 PPO 优于 SAC。

当前提供 **原生 MuJoCo CPU 参考环境＋RSL-RL 适配器**，先验证 MDP、自由轮和学习流程。它不等于 mjlab/Warp GPU 任务，也不把 GPU 网络计算当成 GPU 并行物理。当前会话 `torch.cuda.is_available()=False`；拿到可用 GPU 后，将相同任务定义接入 mjlab，先比较单环境再扩展到 16/64/更多环境，检查自由轮、接触、复位和容量。

1. 跑通单环境、固定命令、无转向基准和随机动作；验证奖励与终止。
2. 训练直行平衡；如果完整目标条件训练探索困难，通过配置把航向变化暂设为 0，再逐步恢复，仍使用同一环境和算法。
3. 加入当前小幅速度／世界航向切换，评估固定预算效果。
4. 无扰动成功率通过后，单独增加可记录的外力扰动实验；基线配置不混入域随机化。

SAC 暂不安装、不同时维护。如果 PPO 在物理已通过验收、经过简单课程后仍不能收敛，再以同一任务和交互预算比较成熟的 SAC 实现。

## 3. 实验 B：机器人上半身动作与转向耦合

B 的首个问题是：**A 给出的转向需求，能否由 G1 的手臂动作通过人车连接真实传递出来，并维持骑行？** 暂不把双腿主动踩踏、Dex3 灵巧抓握学习、全身平衡残差和世界模型一起打开。

计划的数据流：`车辆状态与目标 → 已训练的 A → 曲柄速度参考、转向角参考 → G1 上肢控制策略 → 手臂关节 PD → 手/车把作用力 → 实际转向`。A 的权重冻结，B 的动作是双臂关节位置目标的小幅增量；其余机器人关节先用名义骑姿／随曲柄相位的参考控制。A 的转向角只作为 B 的条件和跟踪目标，**B 中移除直接转向伺服**，不能让教师直接替机器人扭动车把。

B 初期保留曲柄速度驱动用于隔离转向耦合。因此它是“人形机器人操纵转向”的阶段实验，尚不是机器人双腿自主驱动的完整骑行。速度驱动的来源及功率必须在日志和演示中明确。双腿间接驱动车辆是之后的独立任务。

### B 的三个前置验收

1. **手与车把传力。** 现有掌心向下轻触姿态不等于抓握。先在固定架上给手臂小角度指令，验证能双向改变转向角，记录手部接触力与转向力矩。若开放手掌接触难以稳定，首版可使用显式标记的局部手—车把柔顺连接；只能连接机器人与车，不能连接世界，约束反力单独记录，不宣称真实 Dex3 抓握已解决。
2. **承重与腿部参考。** 复核座面承重和骑姿保持；IK 只生成参考，动力学运行时不覆盖机器人根部或腿部状态。腿部按曲柄真实相位跟随，不能拿初始静态屈腿姿态与持续旋转踏板硬碰。台架上确认碰撞、PD 力矩和参考速度合理。
3. **A 的负载适配。** 当前单车约 9 kg，G1＋Dex3 约 34.4 kg，机器人加入会显著改变总质量、质心和惯量。先让 A 在合理的骑乘等效负载上重新适配并验收，再冻结作为 B 的教师；不能认为 9 kg 裸车策略加上机器人自然仍会平衡。刚性负载只用于中间诊断，不替代最终人车动态耦合验收。

B 先在台架上训练／检查双臂转向跟踪，再释放整车。最小新增奖励是实际转向角跟踪、关节动作平滑及姿态偏离；自由骑行保留 A 的速度、航向和失败判据。评价包括转向跟踪误差、动作到转向的延迟、车辆生存率、速度与航向误差及接触／连接反力。教师 A 的目标和 B 的真实转向分别记录。

**B 当前只实现了台架前置检查，尚未实现自由骑行 RL。** `check_rider_steering` 在固定车架上，通过局部座位焊接和两手理想点连接隔离传力；双臂 IK 只计算位置伺服目标，运行中由有限关节力矩带动车把，不覆盖转向状态，也没有转向执行器。`−0.15/0/+0.15 rad` 的指令均通过末段 RMSE `<0.03 rad` 的检查，并记录手部连接反力及上肢力矩。它不验证真实摩擦抓握、腿部踩踏、承重自由骑行，也不能算 B 成功。先让 A 达到目标跟踪验收，再推进受载与自由耦合。

## 4. 实施产物和验收门槛

| 顺序 | 交付 | 进入下一步的条件 |
| --- | --- | --- |
| P0 | 原生自由轮、隔离台架测试 | 方向性、反作用力、耗散、步长检查通过 |
| P1 | A 环境、PPO 训练／恢复／评估入口 | 短训练能更新、保存和加载；相同种子可复现 |
| P2 | A 无扰动骑行基线 | 3 个训练种子，每个至少 100 个未见评估回合；20 秒生存率≥90%，完整回合平均速度向量 RMSE≤0.5 m/s、航向 MAE≤0.2 rad；失败计入成功率分母 |
| P3 | B 手把传力、承重、相位参考与 A 负载适配 | 台架传力与有限力矩控制可复验，无世界固定辅助用于自由骑行 |
| P4 | B 自由骑行耦合 | 无直接转向执行器，机器人动作产生转向；按 P2 同口径并记录接触与约束反力 |
| P5 | 扰动实验 | 无扰动通过后再增加；明确施力位置、方向、幅度、持续时间和恢复成功率 |

规划为 P0/P1 约 1–2 天，P2 约 2–4 天，P3/P4 约 4–7 天；按验收推进，不按日历跳过失败项。受 GPU 可用性和抓握传力结果影响较大。P2 指标是验收目标，不是当前已达到的结果。

## 5. 代码和复现

```text
configs/bicycle_v0.json           # 唯一车辆参数，含自由轮
configs/rl/bicycle_a.json         # A 的目标范围、伺服及训练参数
src/bicycle_sim/models/           # 车辆和轮胎生成
src/bicycle_sim/rl/bicycle_env.py # A 的 CPU 参考动力学任务
src/bicycle_sim/rl/vector_env.py  # RSL-RL 批量接口，当前为 CPU 串行参考
src/bicycle_sim/cli/              # 自由轮审计、训练、评估、回放与上肢转向台架
runs/                            # 检查点、TensorBoard、完整配置快照，忽略 Git
output/phase2/                   # 台架报告与临时验证结果，忽略 Git
```

在项目根目录执行，依赖仍由原有 `uv.lock` 管理，本轮不新增库。若宿主 uv 缓存不可写，可以在命令前加 `UV_CACHE_DIR=/tmp/bicycle-uv-cache`；有 ROS 等路径污染时使用 `python -I`。

```bash
uv run --locked python -I -m bicycle_sim.cli.generate_bicycle
uv run --locked python -I -m bicycle_sim.control.rider_fit
uv run --locked python -I -m bicycle_sim.cli.audit_freewheel
uv run --locked python -I -m bicycle_sim.cli.check_rider_steering
uv run --locked python -I -m pytest -q

# 冒烟训练，不是收敛验收。输出目录必须是新目录。
uv run --locked python -I -m bicycle_sim.cli.train_bicycle \
  --iterations 2 --num-envs 4 --output output/phase2/smoke

# 正式训练；通过 --seed 分别运行多个种子。
uv run --locked python -I -m bicycle_sim.cli.train_bicycle \
  --config configs/rl/bicycle_a.json --output runs/bicycle_a

uv run --locked python -I -m bicycle_sim.cli.evaluate_bicycle \
  runs/bicycle_a --episodes 100 --seed 10000

MUJOCO_GL=egl uv run --locked python -I -m bicycle_sim.cli.play_bicycle \
  runs/bicycle_a --output output/phase2/bicycle_a.gif

# 从检查点继续，写入新目录。环境及车辆配置必须与旧 run.json 相同。
uv run --locked python -I -m bicycle_sim.cli.train_bicycle \
  --resume runs/bicycle_a/model_999.pt --output runs/bicycle_a_continue
```

每次 run 保存实际环境／车辆／算法配置、依赖锁哈希、版本和后端。`--resume` 要求车辆与任务配置一致；奖励或命令范围改变时，可使用 `--warm-start <旧检查点>` 仅加载网络和归一化统计，重置优化器和迭代计数，并在新 run 中记录来源。评估从 run 配置加载，不读取后来修改的默认参数；策略与不转向基准使用同一组评估种子。不转向基准仍使用同一曲柄伺服，速度参考按目标换算，不能拿停止驱动的车作唯一对照。

评估时所有回合都计入生存／目标成功率，速度误差保留失败回合的实际观测值；这些误差对应失败前的时段，必须与生存率一起解读，不能以短回合误差小宣称成功。

## 6. 本轮采用的官方依据

- [MuJoCo general actuator](https://mujoco.readthedocs.io/en/stable/XMLreference.html#actuator-general)：固定增益、仿射速度偏置和力范围；自由轮单向阻尼是本项目在这些组件上的建模选择，不是官方自行车自由轮范例。
- [MuJoCo 积分器](https://mujoco.readthedocs.io/en/stable/computation/index.html#numerical-integration)：隐式速度积分及分支腱阻尼导数的限制，是需要检查步长和阻尼参数的原因。
- [mjlab 与 RSL-RL](https://mujocolab.github.io/mjlab/main/source/training/rsl_rl.html)：现有 on-policy 训练组织方式；具体 API 以当前锁定安装版本为准。
- [Stable-Baselines3 SAC](https://stable-baselines3.readthedocs.io/en/master/modules/sac.html)：如确需 SAC，优先成熟实现；本轮未安装或启用。

`research.md` 中的论文比较不直接决定本项目算法优劣，也不把其中的世界模型、动捕或特技任务引入当前基线。

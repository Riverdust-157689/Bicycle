# 实验C：无骨盆连接的35维全身控制

本文所有35维版本均属于实验C，包括相位残差及直接腿控、有辅助及无辅助版本。实验B仅指上半身策略，腿部由参考控制器驱动。配置和运行目录中的历史`b`前缀保持兼容，完整对应见[实验划分与结果索引](实验划分与结果索引.md)。

截至2026-11-21，最新完成的试验为`configs/rl/bicycle_b_whole_body_direct_noassist_rolling_speed_sac.json`：35维全身控制、腿部全范围直接位置目标、零曲柄辅助、轮地滚阻及2 m/s速度奖励。SAC 16M训练已完成，128个首回合的20秒存活率与速度合格率均为0，仍未形成持续主动踩踏。结果、失败视频和下一步待验证建议见[滚阻与速度奖励SAC16M结果](滚阻与速度奖励SAC16M结果.md)。

下文按推进顺序保留相位残差、带辅助直接控制、无辅助及滚阻速度奖励版本；各段命令对应各自历史工况。当前尚未实施折扣因子0.999、骑姿附近探索或固定车架主动踩踏训练，不要将建议视为已启用配置。

## 初始相位残差基线

独立配置：`configs/rl/bicycle_b_whole_body_sac.json`。从头训练一个35维策略，不加载旧20维策略。全程使用同一个动作空间、网络、优化器和回放池；课程只改变外部曲柄辅助，不冻结或覆盖身体某部分的策略动作。

| 动作列，左闭右开 | 含义 | 目标形式 |
| --- | --- | --- |
| 0:14 | 左右臂各7关节 | 沉降后的名义PD目标＋偏移，幅度0.5 rad、变化率4 rad/s |
| 14:20 | 左右手拇指/食指/中指 | 各一个软件协同闭合量，0.9＋0.1a，变化率0.5/s |
| 20:32 | 左右腿各6关节 | 实际曲柄相位参考＋策略偏移，变化率4 rad/s |
| 32:35 | 腰部yaw/roll/pitch | 沉降后的名义PD目标＋偏移，幅度0.35/0.25/0.35 rad、变化率2 rad/s |

腿部偏移幅度依次为髋pitch/roll/yaw、膝、踝pitch/roll：0.35/0.18/0.18/0.45/0.30/0.18 rad，左右相同。所有关节目标仍受物理关节范围限制，保留原电机PD增益和力矩上限。手指仍是实际Dex3电机的软件协同，不是机械欠驱动。

双腿的相位参考是运动先验，不是覆盖策略输出的另一套腿部控制器：策略12维偏移在每个物理子步持续叠加，保留原相位速度前馈。腰部3维也始终由策略控制。

物理场景删除全部座位/掌把equality，`neq=0`。保留机器人和车架两个自由基座，真实手把、脚踏和车座接触；没有脚踏绑定、转向电机或世界支撑。车座面升高17.13 mm，保持水平、摩擦0.6；座管顶部同步延长，车架其余几何保持原位置。轮胎仍使用已验证的解析椭球。

## GPU初始化

`settle_whole_body`只负责准备姿态：临时固定自行车车架，采用名义上肢/腰部PD和临时曲柄角度保持，重力下沉降3秒。机器人骨盆与双手没有连接。先对齐脚底和踏板，再在沉降期间根据实际骨盆姿态每20 ms重算双腿IK；该IK只用于准备初始状态，训练时不运行。最后0.5秒需要：

- 车座骨盆法向合力>10 N，左右脚踏各>1 N，合格采样比例至少95%。
- 左右手各有受力手指，合格采样比例至少95%；末帧也必须同时满足手、脚、车座条件。
- 最大相关接触穿透<2 mm，骨盆倾角<0.08 rad、总位移<20 mm。
- 骨盆线速度<0.05 m/s、角速度<0.2 rad/s。

通过后还会按沉降后的骨盆姿态重拟合25点周期腿部参考，检查关节限位、脚底位姿误差和周期闭合，再写入`assets/references/g1_bicycle_no_weld.json`。参考文件包含全关节姿态、PD目标、新相位表、模型指纹、原相位表哈希、输入与源码哈希以及临时辅助说明。训练加载该文件中的新相位表，继续叠加12维策略腿部残差。入口只接受通过检查的GPU参考；CPU模式只能输出诊断候选。

默认初始脚踏参考沿横轴倾斜0.08 rad，约4.6°，给右踝pitch的下限留出空间；脚底与踏板使用一致朝向，准备阶段名义间隙0.2 mm。该倾角是初始化与周期参考的几何设置，训练中的踏板转轴仍完全被动，没有增加踏板角度锁定或控制器。

初始化台架的固定车架和曲柄角度保持均不会进入训练。训练从行进状态开始：整车与机器人基座初速2 m/s，曲柄初速3.7037 rad/s，车轮转速与初速匹配；双腿按相位参考导数初始化速度，踏板自身关节反向转动以匹配初始平台朝向。这些是重置时的速度预置，不是静止起步学习。

执行GPU生成：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.settle_whole_body \
  --device cuda:0 \
  --output output/phase2/whole_body_init_gpu_v2
```

该命令应报告`passed: true`。失败时不写训练参考，需先检查`results.json`。输出目录与参考文件均不覆盖已有内容；重新试验时使用新目录及`--reference-output`，并相应修改新配置中的参考路径。

## 曲柄辅助课程

全身任务使用独立的力矩电机，命令为：

\[
\tau_{\mathrm{assist}}=\alpha\,\operatorname{clip}\left(2(3.7037-\omega_{\mathrm{crank}}),-8,8\right).
\]

当alpha为0时，命令与该执行器实际力矩均为零；该电机没有隐式速度阻尼。自行车轴承阻尼和单向传动仍正常存在。

默认课程按交互数执行：

| 全程交互数 | 辅助alpha |
| --- | --- |
| 0–16,777,216 | 1 |
| 16,777,216–25,165,824 | 从1线性降至0 |
| 25,165,824之后 | 0 |

alpha只在每个环境重置时更新，同一回合保持不变，并显式进入观测；避免策略无法观察到动力学变化。课程是初始预算安排，不是已经验证合适的学习进度；需结合检查点的确定性评测判断撤辅助时是否已形成基本平衡。`--crank-assistance 0`或`1`可以进行固定辅助对照。

## 观测、奖励与诊断

观测201维，在原有状态基础上包括35维历史动作、腰腿实际执行偏移、骨盆相对车架的位置/姿态/速度、双脚相对踏板位置、骨盆座面与双脚接触法向力，以及alpha。机器人所有驱动关节状态原本已包含腰部和双腿，不重复添加。

保留原行进平衡奖励及动作幅度/变化惩罚，六指接触奖励最高0.1/s；额外添加最高0.1/s的正向曲柄转速奖励：`0.1*clip(crank_speed/3.7037,0,1)`。各连续奖励乘0.02秒，失败扣5。尚无目标航向、人体姿态或持续双手握把要求。

除了车架倾角>0.65 rad或非轮部件触地，增加机器人骨盆倾角>1 rad、骨盆根部距离座面几何中心>0.4 m的失败判定，防止仅自行车保持直立而机器人已脱落。瞬时失去手、脚或座面接触不直接终止，分别记录。

日志新增骨盆座面法向合力、双脚同时接触比例、辅助系数、曲柄转速、前进速度、外部曲柄正功率、腿部执行器正功率、脚对曲柄的有符号接触力矩/功率估计，以及机器人失稳次数。功率来源必须区分：

- 外部曲柄、腿部执行器正功率按物理子步采样并在控制周期内平均。
- 脚对曲柄的力矩使用真实接触力、接触位置及曲柄轴计算，功率为控制边界采样估计，不是精确积分能量审计。
- 腿部执行器功率包含相位先验PD的作用，不等同于策略残差单独贡献。

只撑满20秒不能证明已学会主动推进：需同时检查无辅助下的持续行进、曲柄转动及脚踏做功，排除主要靠初始动能滑行的情况。

## 冒烟与训练

初始化通过后，先运行零辅助冒烟，检查GPU物理、35维网络更新、局部重置及曲柄电机实际零力矩：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.train_rider \
  --config configs/rl/bicycle_b_whole_body_sac.json \
  --algorithm sac --device cuda:0 --crank-assistance 0 --smoke \
  --output output/phase2/b_whole_body_sac_smoke_v1
```

冒烟是软件检查，不要求32个控制步内学会平衡。新版GPU初始化与零辅助冒烟均已通过，先运行约1M交互短训，检查自由骑行中的接触与学习趋势：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.train_rider \
  --config configs/rl/bicycle_b_whole_body_sac.json \
  --algorithm sac --device cuda:0 --num-envs 128 --transitions 1048576 \
  --output runs/b_whole_body_sac_seed42_1m
```

这轮按默认课程处于全曲柄辅助阶段，alpha=1；35维动作均参与控制，不是无外部动力的自主踩踏验证。GPU沉降检查左右脚最大穿透约0.128/0.108 mm。零辅助冒烟32个控制步内外部曲柄正功率为0，双脚同时受力接触比例约46.1%；该值来自未训练动作探索，需结合后续轨迹判断是否滑脱，而不能直接要求两个脚始终承重。

短训分析后再决定长预算。同一策略的完整课程约32M交互，参考命令如下，不传固定辅助覆盖值：

```bash
uv run --locked --extra training python -I -m bicycle_sim.cli.train_rider \
  --config configs/rl/bicycle_b_whole_body_sac.json \
  --algorithm sac --device cuda:0 --num-envs 128 --transitions 33554432 \
  --output runs/b_whole_body_sac_seed42_32m
```

算法沿用skrl 1.4.2 SAC；网络使用两层256单元，回放容量262,144次交互、批量1024。没有新增依赖。需要PPO对照时可使用同一配置改为`--algorithm ppo`并换输出目录。

## 本地验证边界

本会话CUDA不可见。修正脚踏初始化后，原生CPU候选通过：最后0.5秒手、脚、座面共同接触比例均100%，最大相关穿透约0.343 mm，其中左右脚约0.143/0.113 mm；骨盆位移约1.295 mm，最大线速度约0.00034 m/s。新周期参考位姿误差和闭合误差通过检查。候选位于`output/phase2/whole_body_init_cpu_v5_ik`，没有发布成GPU训练参考。

完整测试87项通过、4项CUDA相关测试跳过；静态检查通过。回归测试包含旧14/20维任务、35维PPO/SAC网络更新、真实零电机力矩、关节动作归属、模型/参考校验、坐姿接触、相对状态旋转不变性与接触力矩计算，以及倾斜骨盆下脚踏对齐与新周期表加载。GPU35维步进、重置、初始化和训练仍需执行上述命令验收。

## 首次GPU初始化失败及修正

`whole_body_init_gpu_v1`的手、脚、车座支撑和骨盆姿态均通过，但最后0.5秒最大穿透6.37 mm，超过保留的2 mm阈值，未发布参考。保存的GPU姿态在原生MuJoCo中重新计算几何，也显示约6 mm脚底—踏板穿透；这只是相同姿态下的几何核查，没有用CPU结果冒充GPU接触力。

首次参考存在两个问题：旧抓握快照里的踏板相对角度与新增完整脚底碰撞盒不匹配，初始右脚重叠约26.9 mm；旧腿部周期参考假定骨盆竖直，而实际沉降后骨盆前倾约1°，沿用旧目标会把脚底参考压到踏板下数毫米。严格要求脚底完全水平又会触及右踝pitch约-0.873 rad的下限。

修正包括：先匹配脚底/踏板初始朝向、保留小名义间隙；沉降期间按当前骨盆重算IK；参考脚踏略微前倾以避开踝限位；用最终坐姿重建周期表。车座、摩擦、软接触和2 mm穿透阈值没有放宽。新日志按车座、左脚、右脚、手分组保存最大穿透、具体几何体、接触位置和力，后续可直接定位GPU异常。

新版本GPU验收需运行`whole_body_init_gpu_v2`；通过后再执行零辅助冒烟，训练命令保持不变。

## 首轮1M的脱踏板评估：方法尚未修改

辅助开启的确定性评测`b_whole_body_1m_assisted_probe`完成128个首回合，平均3.146秒，20秒生存率0%，最长5.12秒。用户观察到左腿脱离踏板后摔倒，保存轨迹证实这是实际接触丢失。

第0号环境约1.28秒起，左脚底中心高出踏板面2 cm且法向接触力低于0.5 N持续至少0.1秒；1.5秒时高差约14.4 cm。该时刻左髋pitch残差约0.181 rad、膝残差约0.209 rad。在相同已记录的骨盆与踏板姿态下，只替换腿部为名义相位目标，正运动学高差约0.8 cm；加上策略残差后约14.6 cm。后两者只是目标可执行性/几何分析，不是重新仿真的对照回合，不能据此证明把残差置零便一定稳定。右脚在更早时间也有间歇性离面。

当前缺口不是完全没有节律：名义参考已与实际曲柄相位同步，左右踏板的半周期关系由机械结构确定。但12维关节残差范围较大，能明显改变脚底位置；相位参考只按初始骨盆姿态拟合，骨盆运动也会使名义脚底偏离踏板。现有奖励只有行进平衡、泛化动作惩罚、手部接触与曲柄转速，没有脚踏相对位置/滑脱惩罚。辅助电机能在脚离开后继续旋转，转速奖励也不能证明双腿正确踩踏。

建议先补固定车架、无骨盆/脚部连接、连续转踏板多个周期的零腿残差对照，确认运动先验和接触本身能动态工作；再做冻结策略的腿残差置零对照。后者是诊断，不是训练课程里冻结腿部动作。

下一版优先考虑脚底相对踏板位置的任务奖励、适度缩小腿残差、对明显且持续的几何脱离设置短宽限后的失败判定。不要把低法向力立即当成脱脚，也不要要求两脚持续大力下压；回程脚可能卸载。按关节追踪固定相位表的强惩罚也不足以适应自由骨盆，脚踏局部坐标下的实际接触几何更直接。曲柄转速奖励可与脚踏几何有效性关联，避免离脚后仍获取完整踩踏收益。

这些修改尚未实施。保持35维动作始终生效，不增加运行时腿部IK覆盖，不绑定双脚。软奖励不能提供绝不脱脚的硬保证，若需要物理保持，需另行建模真实锁踏/脚套等机构并明确任务变化。证据图与几何数据在`output/phase2/b_whole_body_1m_leg_diagnosis`。

## 直接腿部控制＋踏板状态：新1M试验

按用户选择，本轮不实施上述脚踏奖励、脱脚终止或残差收缩方案。新增独立配置`bicycle_b_whole_body_direct_sac.json`，神经网络从头训练；动作仍35维，双臂、手指、腰部接口维持基线。曲柄辅助课程保持原设置，因此这轮1M处于alpha=1。

腿部12维动作直接映射为绝对关节位置目标：

\[
q_{\mathrm{target}}=q_{\min}+\frac{a+1}{2}(q_{\max}-q_{\min}),\quad a\in[-1,1].
\]

范围使用模型原有位置执行器控制限位，已核对与这12个关节的物理角度限位一致。零动作对应各关节范围中点，不是初始坐姿；目标不是增量，也不围绕相位轨迹叠加。没有腿部残差范围或4 rad/s目标限速，保留实际电机PD、力矩上限和物理关节限制。执行每个物理子步时不会调用相位参考或速度前馈。

初始关节姿态仍复用已验收的`g1_bicycle_no_weld.json`，无需重新生成GPU初始化。文件中的相位表及原相位输入仍用于初始化资产的完整性校验，但不在直接模式运行时驱动腿部。直接模式重置的腿关节速度为零，不按相位导数赋予踩踏速度；整车2 m/s、曲柄与轮子的起始转速保持原设置。

## 滚阻验收后的固定速度奖励训练

### 奖励

令v为自行车车架前向的车体系线速度，θ为倾斜角，定义：

```
s(v) = exp(-((v - 2.0) / 0.75)^2)
p(v) = clip((1.5 - v) / 1.5, 0, 1)
rate = (1 + 0.5*exp(-(θ/0.3)^2))*s(v) - p(v)
       - 0.01*||ω||² - 0.005*||a||² - 0.02*||a-a_prev||²
       + 0.1*受力手指比例
       + 0.1*clip(曲柄转速/3.7037037, 0, 1)
reward = 0.02*rate - 5*terminated
```

旧版本的`clip(v,0,1)`在1 m/s以后收益相同，缺少维持2 m/s的动力。新版本在2 m/s最高，减速或过快都会降低速度项。低于1.5 m/s时再施加连续的低速扣分。直立、无动作/角速度惩罚时，速度平衡项在2 m/s为1.5/s、1 m/s约-0.0798/s、0 m/s约-0.9988/s；停车时即使获得全部手指与曲柄小奖励，净速率仍为负。

对本次GPU无动力滑行样本插值到20 ms，假设始终直立、零动作且不终止，仅计算速度与平衡部分，20秒累计约-4.681；持续2 m/s约30。这是奖励函数对照，不是完整机器人策略评测，未计手指、曲柄、动作和终止项。记录在`output/phase2/rolling_speed_reward_check/results.json`。

### 成功指标与终止

20秒任务成功须同时满足：未触发原物理失败条件；全回合至少90%的控制步速度在[1.5,2.5] m/s；最后5秒至少90%的控制步速度也在该范围内。允许短暂恢复，避免仅在结束瞬间冲速就通过。纯滑行台架全回合达标比例约16.4%、最后5秒为0，判为失败；持续2 m/s通过。

此判据只影响任务成功统计，不改变物理失败、20秒截断或SAC的bootstrap语义，不因低速提前终止。策略有机会在减速后恢复速度。

- `survival_20s_rate`与`recent_survival_20s_rate`继续表示原始不倒比例，保留旧结果的可读性。
- `speed_qualified_20s_rate`与`recent_speed_qualified_20s_rate`才是本轮主要成功率，训练中近期窗口为最近1000个完成回合。
- 日志新增速度目标得分与低速扣分均值；评测逐回合保存平均车速、全程/末段达标比例。
- 新配置的`render_rider_probe --successful`和脚踏审计只选择速度也合格的20秒回合，不能再拿停车不倒的样本代表成功。旧配置/旧记录继续使用各自原定义。

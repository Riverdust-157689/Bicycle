# G1＋Dex3 机器人骑车：近期两周推进计划

总体周期按4～5个月安排；以下按10个工作日规划，可据实际开始日期平移。近期目标是搭建能调试、能记录接触、能启动训练的人车仿真平台，为后续可微分世界模型研究提供可靠环境。两周内不以“机器人已经骑稳”作为验收要求。

## 1. 先确定的实施路线

**自行车：先用基本几何体生成参数化 MJCF。** 车架用杆件，车轮先用圆柱形碰撞体，保留转向、前后轮转动、曲柄及脚踏自由度；传动关系显式定义。轮径、轴距、转向轴几何、座高、车把位置、曲柄长度与传动比均可配置。根据 G1 的臂腿可达范围调整车辆，不直接等比例缩小整车；几何变化后同步更新质量和惯量。SW/CAD 资产暂作尺寸和外形参考，不投入主要时间做转换。

基本几何体便于修改和排查问题，但不自动保证动力学正确。轮轴方向、轮地接触、侧滑、质量分布及转向响应需专门验证；视觉模型和碰撞模型分开。暂不增加复杂外观、柔性轮胎和变速系统。

**机器人：优先复用官方 G1 29DoF 与 Dex3-1 资产。** 核对具体 G1 版本、腕部结构、手部型号、关节限位和力矩限制。官方 G1 描述库列有带双手模型，但不能仅凭文件名假定与选定硬件完全一致，需逐项检查。[G1 官方模型说明](https://github.com/unitreerobotics/unitree_ros/blob/master/robots/g1_description/README.md)、[Dex3 官方资产索引](https://github.com/unitreerobotics/unitree_ros/blob/master/robots/README.md)。

**仿真：推荐 mjlab＋MuJoCo Warp，原生 MuJoCo 用于单场景检查。** mjlab 是训练任务组织框架，MuJoCo Warp 是 GPU 物理后端，并非两套互斥方案。先在单场景检查模型，再接入 mjlab 的并行环境。锁定兼容版本与提交号，实际验证碰撞、约束、传动和传感器支持后再扩大并行数。[mjlab 框架论文](https://arxiv.org/abs/2601.22074)、[MuJoCo Warp 文档](https://mujoco.readthedocs.io/en/stable/mjwarp/index.html)。

mjlab 已提供接触对象筛选、接触力/位置/法向等字段及物理子步历史，适合本任务。前期需要区分两类信息：**几何接触力**与**连接约束反力**；如果手脚暂用柔顺连接，约束受力不能用接触传感器代替。先取汇总接触力做控制和日志，保留少量逐接触点数据做诊断；核对坐标系、符号和汇总规则，避免多接触相消或漏掉子步内碰撞。[mjlab 接触传感器文档](https://github.com/mujocolab/mjlab/blob/main/docs/source/sensors/index.rst)。

**同步调研，累计控制在1～2个工作日。** 第一周筛奖励、仿真配置和代码；第二周筛动捕并尝试回放一个候选片段。有多人时可独立推进；单人则穿插在运行与训练等待期间，不阻塞建模。

## 3. 两个关键实现约定

**先保证接触与动作接口可调试。** Dex3 首先采用固定闭合参考，不让策略同时学习全部手指；手脚必要时使用可开关的局部柔顺连接，且记录反力。辅助模式只用于调试，人与车整体不得固定到世界。先用固定架检查踩踏，再撤去固定架测试运动；后轮临时电机驱动只能作为轮地调试模式，不能计作机器人主动骑行。

**先用基础算法建立闭环，再引入可微分世界模型。** 首选 PPO＋关节 PD＋名义踩踏参考，策略输出少量躯干、双臂和下肢残差；暂不同时比较多种算法。奖励先包含横滚稳定、速度/航向跟踪、手脚保持、动作平滑及能耗，分项输出；倾倒、严重穿模或异常触地终止。具体权重在物理检查后确定。最终骑车评价需排除仅靠初速度滑行、外部驱动和辅助支撑获得的成功。

从第一版环境就保存观测、动作、下一观测、终止原因、控制周期、接触摘要和辅助模式标记。完整仿真状态另作调试与回放使用，不能不加区分地输入策略。后续可微分世界模型从这些状态转移学习动力学，并让策略梯度穿过预测轨迹；不把 GPU 仿真本身等同于可微分世界模型。

## 4. 开源资源：先查这些，明确可用程度

| 资源 | 已确认的用途 | 两周内需要补查的内容 |
| --- | --- | --- |
| [CycleRL](https://cpnt-lab.github.io/CycleRL/) | 自主自行车的 PPO、平衡/速度/航向奖励与仿真设计参考 | 当前主页展示论文背景与视频；训练代码和完整配置是否公开仍需核对，不能按现成环境排工期 |
| [autonomous-bike-rl](https://github.com/vjardimb/autonomous-bike-rl) | 已有 MATLAB/Simulink 源码，包含手动控制、转向和速度控制任务 | 提取复位、参数与奖励设计；不直接移植其仿真后端，也不把自主车动作接口套给人形机器人 |
| [自行车路径跟踪与稳定研究](https://link.springer.com/article/10.1007/s11044-026-10144-x) | 已公开论文，包含奖励设计与动力学任务说明 | 核对附带代码、配置和许可，整理可借鉴项 |
| [CMU MoCap](https://mocap.cs.cmu.edu/) / [AMASS](https://amass.is.tue.mpg.de/) | 人体动作检索入口 | 尚未确认可直接使用的骑车序列；需找到具体序列号、格式、下载条件，检查是否有完整踩踏和车体参考 |

动捕最多投入1天检索和样例检查；没有合适数据就采用“脚踏圆周轨迹＋IK＋躯干/手臂参考”，不等数据。即使找到人体骑车动捕，也需结合车体尺寸重定向，不能直接作为 G1 控制指令或接触力真值。AMASS 按研究许可获取，不将“可下载”写成可任意再分发。[AMASS 许可](https://amass.is.tue.mpg.de/license.html)。

调研表每项记录：原始链接、是否能下载、代码/数据许可、可提取文件、与人形骑车的差异。论文、视频、训练代码和可执行动捕分别标记。

## 5. 两周验收与后续节奏

第5天检查：人车尺寸与运动范围合理；没有用世界固定约束伪造稳定；接触日志可解释。第10天检查：物理步长减半后主要响应无明显异常；脚本动作可回放；并行复位正常；PPO 链路跑通；模型与轨迹日志可复现。未通过物理检查，优先修正平台，不用长时间训练掩盖问题。

建议总体安排：**第1月**完成平台与人车接触/踩踏闭环；**第2月**稳定 PPO 基线与固定评估协议；**第3月**接入可微分世界模型和轨迹反传；**第4月**完成无模型、模型样本、可微分反传的对照及停止梯度消融；**第5月（机动）**做重复种子、经验迁移和成果整理。若总周期仅4个月，优先保留可微分世界模型的主对照，将跨技能迁移与实机探索设为拓展。

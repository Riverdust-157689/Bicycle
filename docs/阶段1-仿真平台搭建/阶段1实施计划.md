# 阶段1实施计划：确认设计的平台落地

阶段目标：在已确认的G1＋Dex3自行车几何方案上，完成接触、脚本控制与并行仿真平台。车辆参数统一读取`configs/bicycle_v0.json`，当前尺寸与验证结果见[阶段1进度记录](阶段1进度记录.md)，不再维护多套尝试方案。

## 项目结构与环境

- `assets/g1_dex3/`保留原始机器人资产及许可证；适配在生成代码中进行，仿真不依赖旧项目路径。
- `assets/bicycle/`保留同一设计的自由运动场景与固定架诊断场景。
- `assets/scenes/`保留当前人车组合场景。
- `src/bicycle_sim/models/`负责几何与MJCF生成；`control/`负责IK、参考运动和接触几何检查；`cli/`提供可复现命令。
- 后续按需要增加`sensing/`与`tasks/`，分别负责统一接触日志和mjlab任务，不预建无功能模块。
- `tests/`验证结构与物理行为；`output/`存放Git忽略的生成结果。

使用单一uv项目、`uv.lock`和`.venv`，日常运行`uv run --locked python -I ...`。依赖变更统一用uv维护，不引入GCRL环境、手工pip覆盖或源码补丁式框架分叉。安装及完整复现命令见根目录README。

## 执行顺序与验收

| 步骤 | 当前状态／后续任务 | 验收要求 |
| --- | --- | --- |
| S0 环境与资产 | 独立环境及CPU导入已完成；GPU可见性待确认 | 同一锁文件可复现，GPU项单独记录，不以CPU结果代替 |
| S1 单车模型 | 当前设计已确认，生成及单车测试通过 | 保留生成确定性、传动、轮地接触和步长敏感性回归 |
| S2 人车适配 | 初始手部几何、手脚位置可达及前部净空检查已完成 | 后续姿态/碰撞改动均重建场景并复验，不修改硬件限位强行拟合 |
| S3 动态接触与控制 | 下一步重点，约2～3个工作日 | 固定架上调试PD、名义踩踏与手掌轻接触；确认腿部经脚踏做功，手臂能够操纵车把，记录接触和约束反力 |
| S4 GPU任务封装 | S3稳定后约2～3个工作日 | mjlab组织任务，MuJoCo Warp后端按1→16→64环境递增；重复复位无串扰、容量溢出和非有限状态 |

先调固定架上的动作与接触，再检查自由运动。固定架不计入骑行成功，正常骑车模式不增加独立后轮驱动或世界固定约束。S3/S4通过后，进入PPO基础骑行训练与统一评估，随后研究可微分世界模型的训练加速。

## 接触与数据接口

必要接触对：前后轮—地面、左右手/手指—握把、左右足底—脚踏、臀部—座面、车架及机器人异常触地。优先使用锁定版本mjlab的配对接触传感器，先做最小接口测试再扩展到并行场景。

按物理子步记录接触数量、位置、法向、力和持续时间，明确受力主体及坐标系；控制步另做汇总，避免遗漏短接触。验证压入/移离响应及左右接触不会串扰。若使用局部柔顺连接，约束反力必须另记，不能拿碰撞接触力替代。

轨迹统一保存`obs/action/next_obs`、终止原因、物理/控制周期、辅助模式、接触摘要与配置哈希。完整仿真状态供复位/回放，不能不加区分地输入策略。后续可微分性来自学习到的动力学模型及轨迹反传，不要求对物理接触求解器反向传播。

## 阶段边界

当前确认的是几何方案；实心圆柱轮胎、等效惯量与理想传动均需在后续动态检查中检验。静态相位网格不能覆盖连续扫掠、受力后偏移或所有关节余量。完成接触承重、动态控制和GPU验收前，不把关键帧播放或位置IK称为已学会骑车。
